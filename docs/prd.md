# 闪记（Shanji）产品需求文档

**版本**: v0.2  
**日期**: 2026-03-13  
**状态**: 迁移版草案

## 1. 产品概述

### 1.1 产品定位

闪记（Shanji）是一款桌面端 AI 语音输入工具。用户通过全局快捷键唤起录音，对着麦克风说话，系统将语音实时转写为文本，并可选进行 LLM 智能改写，最终自动输出到当前光标所在位置。

本轮产品调整的重点不是功能重做，而是交互体验重构：现有实现基于 Tauri + WebView，核心功能已基本具备，但主观使用感仍有迟滞。下一阶段将把 UI 架构迁移为 `Rust + Slint`，目标是降低输入反馈延迟、减少界面层不确定性，并统一为纯 Rust 技术栈。

### 1.2 核心价值

- 本地推理，隐私优先：语音识别在本地完成，音频不上传
- 低摩擦输入：不切换窗口，直接在任意输入框中说话即输入
- 智能改写：可选接入 LLM，把口语表达整理为可直接发送或提交的文字
- 轻量原生：去除 WebView 带来的额外交互层，追求更直接的桌面响应
- 跨平台：Windows、macOS、Linux

### 1.3 目标用户

- 知识工作者：文档、邮件、IM、代码注释、PR 描述
- 高频语音输入用户：希望替代部分键盘输入
- 需要快速记录内容的用户：会议、灵感、任务记录
- 对桌面工具响应速度敏感的用户

## 2. 本轮架构约束

| 层级 | 约束 |
|------|------|
| UI 框架 | 采用 `Slint`，不再继续投入 WebView 前端 |
| 核心语言 | 统一为 Rust |
| 语音识别 | 继续沿用 FunASR Paraformer + ONNX Runtime |
| 智能改写 | 继续使用 OpenAI 兼容 API 方案 |
| 跨平台 | Windows 10+、macOS 12+、主流 Linux 桌面 |
| 迁移策略 | 优先复用现有 Rust 业务模块，先替换 UI 壳层，再逐步清理 Tauri 依赖 |

## 3. 本轮产品目标

### 3.1 体验目标

- 缩短“按下快捷键 -> 悬浮窗反馈”的主观等待感
- 缩短“停止录音 -> 处理中反馈”的界面切换迟滞
- 降低设置窗口、历史窗口、Overlay 的打开和刷新卡顿感
- 保持现有核心功能完整，不因换 UI 框架造成能力倒退

### 3.2 非目标

- 本轮不改变 ASR 模型路线
- 本轮不重做产品功能定义
- 本轮不新增移动端支持
- 本轮不先做大规模视觉改版，先完成架构迁移

## 4. 核心功能范围

以下功能在迁移到原生 UI 后必须继续保留：

### 4.1 语音录入与转写

- 全局快捷键启动/停止录音
- Push-to-Talk 与 Toggle 两种模式
- 录音过程中的实时结果反馈
- VAD 自动停录
- 麦克风设备选择与电平测试

### 4.2 模型与识别

- 本地 Paraformer 模型加载
- 模型下载、校验、切换、删除
- 多语言或多模型切换
- 自定义热词/词库导入与启停

### 4.3 智能改写

- 改写开关
- Prompt 模板与自定义
- OpenAI 兼容接口配置
- 改写流式反馈

### 4.4 文本输出

- 自动粘贴到当前光标位置
- 剪贴板回写与恢复
- 输出格式控制
- 历史记录存储与检索

### 4.5 桌面交互

- 主窗口
- 设置窗口
- 历史记录窗口
- 录音悬浮窗 Overlay
- 系统托盘
- 全局快捷键

## 5. 原生 UI 需求

### 5.1 窗口模型

- 主窗口：用于展示整体状态和导航
- 设置窗口：集中管理音频、识别、改写、输出、快捷键等配置
- 历史记录窗口：检索与复用过往内容
- Overlay：始终轻量、可置顶、低干扰

### 5.2 交互要求

- Overlay 必须支持无边框和置顶
- 状态更新不应依赖前后端异步 IPC 往返
- 录音状态、识别状态、改写状态必须能直接映射到 UI 状态机
- 长时间后台运行时，窗口和托盘状态不能出现不同步

### 5.3 性能要求

- 冷启动应优先进入可交互状态
- Overlay 展示与隐藏必须足够轻
- 设置页切换不应出现明显掉帧
- 高频状态刷新场景下，CPU 和内存开销应可控

## 6. 成功标准

- 用户在相同机器上主观感知到界面更“跟手”
- 与现有 Tauri 版本相比，主窗口和 Overlay 的打开反馈更直接
- 原有核心功能在迁移后均可正常使用
- 文档、目录结构、开发流程不再把 WebView 当作长期架构

## 7. 风险与约束

- Linux 下托盘、全局快捷键、输入模拟的行为仍受桌面环境差异影响
- Wayland 对全局监听与自动输入能力的限制并不会因为更换 UI 框架而消失
- UI 迁移会涉及窗口管理、状态同步、打包方式的整体调整

## 8. 当前结论

- 保留现有 Rust 业务能力
- 放弃继续扩展 Tauri WebView 前端
- 原生 UI 选型确定为 `Slint`
- 代码迁移稍后开始，本次仅统一文档方向
